# 로컬 진행 저장 구현 기준

상태: 웹 localStorage 어댑터와 게임 연결 구현 및 자동/브라우저 검증 완료. iOS 네이티브 저장은 별도 검증이 필요합니다.

## 범위

새로고침/재실행 후 현재 레벨과 같은 카드 제거 상태, center, 남은 덱, 클리어/실패 상태를 복원합니다. 음소거 옵션과 클리어한 레벨 목록을 유지합니다. 자체 서버, 계정, 클라우드, 결제 권한은 다루지 않습니다.

## 저장 구조

키는 `picture-blast-solitaire.save`로 고정합니다.

```json
{
  "schemaVersion": 1,
  "currentLevelId": "level_2",
  "levelSignature": "현재 레벨 내용의 결정적 서명",
  "completedLevelIds": ["level_1"],
  "actions": [{"type": "remove", "cardId": "board_4"}],
  "options": {"soundOn": false},
  "imageRef": null
}
```

- `currentLevelId`는 배열 인덱스가 아닌 안정적인 레벨 id입니다.
- `levelSignature`는 mode, startingCenterCard, 순서 있는 cards의 value/suit, deck으로 만듭니다. 이 필드들을 고정 순서로 JSON.stringify한 문자열도 허용합니다. 제목/solution/옵션은 제외합니다. 보안 서명이나 구매 검증으로 사용하지 않습니다.
- 카드 전체 상태를 신뢰해서 로드하는 대신 현재 레벨의 성공한 remove/draw 행동만 저장합니다. 복원 시 고정 초기 상태에서 기존 규칙 함수로 행동을 순서대로 재생합니다.
- 옵션과 이미지 참조는 별도로 검증합니다. `imageRef`는 null 또는 `{kind:"user",name,size,lastModified}`만 허용합니다. 문자열 길이와 숫자 범위를 제한하고 그 외 필드는 제거합니다.
- URL, Blob URL, 이미지 바이너리, HTML, 구매 권한, 광고 보상은 저장하지 않습니다.
- `completedLevelIds`는 실제 클리어 이벤트에서 id를 중복 없이 추가하며 로드 시 현재 팩에 존재하는 id만 남깁니다. 로컬 값은 부정 조작 방지 증거가 아닙니다.

## 복원과 오류 처리

1. 레벨 파일 검증을 마친 후 저장을 읽고 복원합니다. 복원 전 제어 버튼은 비활성화하고 초기 상태로 기존 저장을 덮어쓰지 않습니다.
2. 저장이 없으면 첫 스테이지와 기본 옵션으로 시작합니다.
3. 정상 저장이면 같은 판을 재생하고 최종 상태에서 렌더링합니다. cleared/failed/blocked/팩 완료도 그대로 복원합니다.
4. 레벨 id가 유효하되 서명이 달라지거나 행동이 무효이면 해당 레벨의 초기 상태로 돌아갑니다. 복원 가능한 옵션/클리어 목록은 유지하고 짧게 안내합니다.
5. 현재 id가 사라졌으면 알려진 클리어 목록을 보존하고 팩 순서상 첫 미클리어 레벨로 이동합니다. 모두 클리어했다면 마지막 레벨로 이동합니다.
6. 알 수 없는 행동, 중복 제거, 합법 수가 있는데 실행한 Draw, 덱 초과 사용, 완료 뒤의 추가 행동은 무효입니다. 로그 길이는 해당 cards 수 + 초기 deck 수 이하로 제한합니다. 무효 로그를 일부만 재생한 상태로 계속하지 않습니다.
7. 깨진 JSON/잘못된 필드는 예외를 UI까지 전파하지 않습니다. 읽을 수 있는 유효 필드만 복원하거나 기본 상태로 시작하고 저장 복원 안내를 표시합니다.
8. 미래 schemaVersion은 지원한다고 가정하지 않습니다. 현재 세션은 메모리로 플레이하고 기존 원문을 자동으로 덮어쓰지 않습니다. 이전 저장 버전이 아직 없으므로 허구의 v0 마이그레이션은 만들지 않습니다.
9. 브라우저 저장 접근/용량 제한 오류에서도 메모리 게임은 계속됩니다. 사용자가 저장되지 않는 사실을 알 수 있게 별도 비차단 메시지를 표시합니다. 상태 안내(playing/blocked/cleared/failed)를 덮어쓰지 않습니다.
10. 재실행 후 이미지 데이터가 없으면 기본 이미지와 재선택 안내를 표시합니다. 저장된 imageRef가 기본 이미지 표시로 인해 자동 삭제되지 않아야 합니다. 실제 업로드 후 안내를 해제하고 새 참조를 저장합니다.

## 이벤트와 플랫폼 경계

- 성공한 카드 제거/Draw, 다시하기, 다음 스테이지, 음소거 토글, 이미지 참조 변경 후 저장합니다.
- 무효 클릭은 행동 로그에 넣지 않습니다. 다시하기와 다음 스테이지는 해당 판의 로그를 비웁니다. 클리어 목록과 옵션/이미지 참조는 유지합니다.
- pagehide만을 유일한 저장 시점으로 사용하지 않습니다.
- 비동기 `getItem(key)` / `setItem(key, value)` 저장 어댑터를 주입할 수 있게 분리합니다. 이번 기본 구현만 localStorage를 사용합니다. 네이티브 저장 플러그인은 설치하지 않습니다.
- 비동기 쓰기는 스냅샷 생성 시 복사하고 순서를 보장합니다. 빠른 연타/재시작/옵션 변경에서 오래된 쓰기가 나중 값을 덮지 않아야 합니다. 실패한 쓰기로 다음 저장 큐가 영구 정지하지 않게 합니다.
- 저장의 기대된 실패를 레벨 파일 로딩 실패 화면으로 표시하지 않습니다. 저장 로드가 실패해도 기본 게임을 시작합니다.
- 렌더링 함수에 저장 부작용을 넣지 않습니다.

## 구현/검증 산출물

- `web-prototype/js/save.js`: 저장 어댑터, 직렬화/검증/복원, 순서가 보장되는 저장 API.
- main.js와 필요한 최소 HTML/CSS 연결. 저장/이미지 안내는 aria-live="polite"인 별도 영역 사용.
- 기존 스테이지 데이터와 규칙은 유지합니다. 저장 모듈은 DOM/오디오에 의존하지 않습니다.
- scripts/check-repo.mjs에 새 파일 포함. README/DEV_QUICKSTART는 실제 동작에 맞게 수정.
- 검증용 Node 실행 코드를 별도 출력합니다. 테스트 프레임워크/새 테스트 파일은 추가하지 않습니다.
- 검증 항목: 중간 판/Draw/클리어/실패 복원, 다시하기/다음/마지막 팩, 옵션 유지, 이미지 폴백, 깨진/과대/미래 버전 저장, 사라진/내용 변경 레벨, 저장 접근 오류, 느린/실패한 비동기 쓰기 순서, 입력 객체 불변성.

## 구현 상세

- `createSaveStore(adapter).load(key)`는 `{rawText, error}`를 반환합니다. 읽기 오류나 과대/미래 버전을 감지하면 세션 쓰기를 차단하여 원문을 보호합니다.
- `save(key, slot)`은 호출 시 허용 필드의 스냅샷을 만들고 `{ok, reason?}`으로 완료되는 Promise를 반환합니다. 직렬 큐에서 한 쓰기가 실패해도 다음 쓰기는 실행됩니다.
- 원문 저장은 최대 100,000자, 로그는 현재 레벨 카드 수 + 초기 덱 수로 제한합니다. 이미지 파일명은 1~255자이며 음수/비정수/안전 범위 밖 숫자와 URL/HTML 형태의 이름은 참조에서 제외합니다.
- 저장은 브라우저 origin에 종속됩니다. 개발 서버 포트/브라우저가 다르면 같은 저장을 읽지 않습니다.
