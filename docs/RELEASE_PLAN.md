# iOS 우선 출시 계획

기준일: 2026-11-17. 이 문서는 개발 목표와 완료 조건이며 구현 완료를 뜻하지 않습니다.

## 사용자 결정에 따른 개발 순서 변경

최신 정정: 드래그로 어느 카드끼리든 교환하고 빈칸 이동은 금지합니다. 세로 그림 완성 시 제거·낙하·연쇄하며 모두 제거하면 클리어합니다. `docs/PICTURE_SWAP_SPEC.md`가 최신 기준입니다. 이전 클릭 제거 구현과 아래 QA 수치는 이 규칙의 완료 근거가 아닙니다. 지금 최우선 작업은 새 코어 구현과 검증이며 상점/광고 작업은 계속 보류합니다.

2026-11-17 사용자가 그림 위·아래 조각 짝맞추기로 규칙 변경을 선택했습니다. `docs/PICTURE_MATCH_SPEC.md`의 실제 그림 카드 플레이를 통합하고 웹 검증을 완료했습니다. 기본 진입점은 새 게임이며 숫자 ±1 게임은 별도 페이지에 보존합니다. 상점/플랫폼 경계 지시서는 보류하며 새 코어 플레이의 사용자 테스트 후 다시 맞춥니다. 첨부 스크린샷에서 가공한 카드 이미지는 개발 검증용이고 출시용 사용 권한을 확인한 콘텐츠가 아닙니다.

## 이전 구현 상태: 클릭 그림 짝맞추기 (사용자 정정으로 교체 예정)

- 실제 화병 그림 6종, 고정 스테이지 3개: 12장(4×3), 24장(6×4), 보스36장(6×6).
- 같은 그림의 반대 조각 매칭, 선택/해제/불일치, 완성 미리보기, 무료 힌트/남은 카드 섞기, 재시작/다음 단계/팩 완료.
- 새 전용 저장 키로 판/섞인 배치/음소거/클리어 기록 복원. 레거시 저장 키 보존, 이미지 로딩 실패/저장 실패/미래 데이터 보호.
- 2,016개 카드 조합과 360개 섞기·저장 왕복 자동 검증, 브라우저 3개 스테이지 전체 진행·클리어와 모바일 화면 확인.
- 상점/실제 결제/광고/네이티브 앱은 미구현. 재미/난이도/리텐션은 사용자 플레이 테스트가 필요합니다.

## 제품 목표

- 기본 무료인 그림 위·아래 조각 짝맞추기 캐주얼 게임.
- 짧은 플레이, 이해하기 쉬운 규칙, 그림 수집과 단계 진행을 중심으로 반복 플레이 동기를 제공합니다.
- IAP와 IAA로 수익화하며, 자체 서버 없이 시작합니다.
- iOS 출시 후 같은 게임 로직과 콘텐츠로 Android를 지원합니다.
- Codex는 검토/통합/검증, Gemini는 사용자가 전달하는 프롬프트를 통한 큰 구현과 콘텐츠 제작을 담당합니다.

## 현재 상태: 숫자 ±1 레거시 프로토타입

- HTML/CSS/JavaScript 모듈 기반 웹 프로토타입.
- main 25장 / boss 9장, ±1 및 1↔13 규칙, reveal 비율 계산.
- main 16장 / boss 8장 유한 덱과 playing/blocked/failed/cleared 상태.
- 이미지 메모리 업로드, 사운드/햅틱 토글, 모바일 레이아웃.
- 규칙/UI 자동 검증 및 브라우저에서 클리어·실패·재시작 확인.
- 고정 스테이지 6개, 해 경로 검증, 다시하기/다음 단계/팩 완료 흐름 구현.
- 버전1 로컬 세이브, 행동 재생 복원과 옵션 영속화 구현. 저장 오류/미래 버전 보호 검증.
- 실제 카드 위치별 그림 조각 공개와 첫 실행 인라인 튜토리얼/수동 도움말 구현.
- 클리어 기록 기반 컬렉션/해금, 잠금 표시, 큰 보기 구현. 6개 항목은 검증용 기본 아트 한 장을 공유하며 출시용 개별 아트는 별도 필요.
- 상점, 결제, 광고, 네이티브 앱은 아직 미구현. 웹 저장은 기기 간 동기화/재설치 복원을 보장하지 않음.

## 기술 방향

현재 HTML5 코드를 유지하고 Capacitor를 통한 로컬 번들 iOS/Android 앱을 기본 경로로 삼습니다. 지금 단계에서 Unity/Godot 재작성은 하지 않습니다.

출시용 번들은 게임 파일만 포함해야 하며 현재 문서까지 복사하는 dist를 그대로 앱 패키지로 쓰지 않습니다. 네이티브 의존성 도입 시 버전·라이선스·유지보수 상태를 확인하고 잠금 파일로 고정합니다. 웹 빌드에 운영용 server.url을 지정하지 않습니다.

게임 로직은 광고/스토어/Game Center SDK를 직접 호출하지 않습니다. ads, purchases, achievements, storage, telemetry 인터페이스를 통해 연결합니다. 웹에서는 명시적인 개발용 모의 구현 또는 unavailable 결과를 사용합니다. 출시 모드에서는 모의 구매·광고 성공을 허용하지 않습니다.

네이티브 브리지/플러그인의 구체 선택은 호환성과 비용을 확인한 뒤 결정합니다. Windows에서 모의 연결이 통과해도 실제 iOS 연결 완료로 표시하지 않습니다.

## 초기 수익화 범위

1. 자발적인 보상형 광고: 실패 후 추가 기회 등의 선택지. 광고를 보지 않아도 기본 플레이와 재시작이 가능합니다. 실제 보상 콜백을 받은 경우에만 보상을 한 번 지급합니다.
2. 전면 광고: 튜토리얼 이후 판 사이 자연스러운 전환에서만 제한적으로 노출합니다. 노출 간격과 세션별 상한은 조절 가능한 설정으로 둡니다. 플레이 도중 강제 중단하지 않습니다.
3. 첫 영구형 IAP: 강제 전면 광고 제거. 상품 설명에서 선택형 보상 광고가 남는다는 점을 명확히 안내하고, 구매 복원 버튼을 제공합니다.
4. 콘텐츠 가치가 확인되면 영구형 아트 팩을 추가할 수 있습니다. 초기에는 구독과 유료 소모성 재화를 보류하여 운영·복구 복잡도를 줄입니다.

AdMob 네이티브 SDK를 우선 후보로 검토합니다. 개발/QA에서는 테스트 광고만 사용합니다. 사용자 추적 동의, 지역별 동의, SDK 데이터 수집 및 App Privacy/Privacy Manifest를 실제 SDK 구성에 맞춰 처리합니다. ATT를 거부해도 플레이를 허용하며, ATT 거부를 보상으로 유도하지 않습니다.

광고가 없거나 오프라인이면 보상 광고 버튼은 정직하게 이용 불가를 표시합니다. 기본 게임은 계속 동작합니다. 로컬 테스트 버튼으로 결제 권한을 부여하지 않습니다.

영구형 구매 권한은 기기 내 StoreKit 검증과 복원을 기준으로 설계하고, 구매 취소·보류·환불·중복 콜백을 구분합니다. consumable은 재설치·기기 이동 후 잔액 복구를 자체 서버 없이 보장하기 어려우므로 첫 출시에서 제외합니다. 자체 서버 없는 구조는 변조나 보상 부정 수급을 완전히 막지 못합니다.

## 저장과 리텐션

- 버전이 있는 로컬 세이브: 해금 스테이지, 클리어 기록, 아트 컬렉션, 옵션.
- 저장 오류/손상/버전 변경을 처리하고 앱 종료·재실행을 검증합니다. 네이티브 어댑터 도입 시 웹 저장 마이그레이션 여부를 명시합니다.
- 구매 권한은 일반 세이브 필드만으로 신뢰하지 않습니다.
- 업로드 이미지 바이너리와 Blob URL은 세이브에 넣지 않습니다. 재실행 후 사용자 이미지가 없으면 기본 이미지와 재선택 안내를 제공합니다.
- 앱에 동봉한 레벨과 아트로 인터넷 없이 진행합니다. 외부 이미지 API를 플레이 중 호출하지 않습니다.
- 단계별 그림 reveal, 컬렉션, 짧은 목표, 주기적 보스전을 순차 검증합니다. 첫 스테이지 팩에서 재미를 확인한 뒤 콘텐츠를 확장합니다.
- 일일 퍼즐은 기기 내 날짜/seed로 만들 수 있지만 시계 변경과 치팅을 막는 구조는 아닙니다.
- D1/D7 잔존율, 완료율, 실패·재시도율, 광고 선택률, IAP 전환을 측정 후보로 둡니다. 설치별 코호트 지표는 동의 및 수집 설계를 갖춘 분석 도구가 있어야 확인할 수 있습니다. 오프라인 테스트만으로 수익성이나 잔존율을 입증하지 않습니다.

## Game Center와 Firebase

첫 출시는 랭킹 없이 진행/컬렉션을 우선합니다. iOS 업적이 제품에 유효하고 네이티브 검증 일정이 허용되면 Game Center 업적을 추가합니다. 비로그인·네트워크 오류가 플레이를 막지 않아야 합니다.

동일한 보드·seed·덱·보상 조건을 갖춘 챌린지와 점수 규칙이 검증된 뒤에만 Game Center 리더보드를 도입합니다. 무작위 보드나 구매/광고 혜택이 섞인 플레이를 그대로 경쟁 순위로 비교하지 않습니다. Game Center는 Apple 플랫폼용이며 Android와 통합된 크로스플랫폼 순위가 아닙니다.

Game Center는 별도 자체 DB/서버를 운영하지 않는 iOS 소셜 기능의 우선 선택입니다. Firebase는 첫 출시 필수 의존성이 아닙니다. 필요하면 Analytics/Crashlytics 등 무료 항목부터 검토하되 Capacitor 네이티브 연결 여부를 따로 확인합니다.

크로스플랫폼 랭킹을 요구할 때만 Firebase 또는 다른 관리형 백엔드를 재검토합니다. 클라이언트가 점수를 자유롭게 쓰는 Firestore 랭킹은 경쟁 무결성을 보장하지 않습니다. 검증 함수/인증/쿼터/남용 방지를 포함해 비용을 산정합니다.

## 비용 원칙

- 자체 API/DB/서버: 첫 출시에서 월 고정비 0을 목표로 합니다. 스토어 등록비, 매출 수수료, 아트/법무 등 모든 비용이 0이라는 뜻은 아닙니다.
- Apple Developer Program: 공식 공개 기준 연 US$99. 지역별 결제 금액/세금은 실제 가입 화면에서 확인합니다.
- Small Business Program: 자격을 갖추고 승인되면 유료 앱/IAP 수수료 15%. 자동 적용이 아니며 관련 계정 매출 기준과 지역별 계약 조건을 확인합니다. 일반적으로 언급되는 30%를 모든 지역/계약의 확정 수수료로 가정하지 않습니다.
- Game Center: 기존 Apple 개발자 프로그램 안에서 자체 서버 없이 활용하는 방향. 별도 서버 요금 항목을 두지 않되 도입 시 최신 조건을 재확인합니다.
- Firebase Spark: 무료 한도 내에서 활용 가능. Cloud Functions는 Spark에서 제공되지 않아 Blaze가 필요합니다.
- Firebase Blaze: 사용량 과금. 무료 할당량이 있어도 청구 계정이 필요하며 예산 알림은 지출의 강제 상한이 아닙니다.
- 필요가 생겨도 우선 플랫폼 기본 서비스 또는 무료 플랜을 선택합니다. 초과가 예상되면 DAU·세션 수·읽기/쓰기·전송량으로 비교한 후 제안하고 활성화합니다. 현재 사용량 없이 특정 유료 서비스를 최저가라고 확정하지 않습니다.

## Windows 개발 순서와 완료 조건

1. 레벨 데이터 로더 + 작은 고정 스테이지 팩. 무작위 판만 반복하는 상태에서 실제 단계 진행으로 전환하고, 각 레벨의 클리어 경로를 재생해 검증합니다.
2. 클리어/실패/다음 스테이지 UI, 튜토리얼, 실제 조각 reveal, 아트 컬렉션과 반복 플레이 흐름.
3. 로컬 진행 저장/복구/마이그레이션, 옵션 영속화, 앱 재개와 중복 보상 방지 모델.
4. 상점 UI, 상품 카탈로그, 구매 복원 흐름, 구매/광고 플랫폼 인터페이스와 성공·취소·보류·실패 시나리오 검증.
5. 광고 배치·노출 제한·동의 흐름, 오프라인/미지원 처리, 필요한 업적 이벤트 분리.
6. 출시용 게임 전용 빌드, Capacitor 설정과 가능한 Windows 측 동기화, 의존성 버전 고정 및 Mac 인계 문서.
7. 전체 플레이 회귀 점검, 모바일 화면/접근성/저사양 성능, 라이선스가 확인된 아트/폰트, 개인정보처리방침·지원 페이지 초안과 스토어 자료 준비.

Windows 완료 기준은 게임/콘텐츠/로컬 저장/상점과 광고 흐름/플랫폼 경계/패키징 준비가 검증된 상태입니다. 실제 구매·실제 광고·Game Center·iOS 실기기·심사 통과를 포함하지 않습니다. 네이티브 의존성 검증 전까지 iOS 출시 준비가 완전히 끝났다고 표시하지 않습니다.
