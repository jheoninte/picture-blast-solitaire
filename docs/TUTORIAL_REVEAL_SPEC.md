# 튜토리얼과 그림 조각 공개 구현 기준

상태: 구현 및 자동/브라우저 검증 완료. 기존 게임 세이브 스키마는 유지합니다.

## 목표와 범위

그림 전체의 opacity가 올라가는 현재 표현을 카드별 그림 조각 공개로 바꿉니다. 짧고 건너뛸 수 있는 규칙 안내를 추가합니다. 카드 규칙, 스테이지 데이터, 게임 저장 스키마는 유지합니다. 상점/광고/클라우드/컬렉션은 이번 범위에 넣지 않습니다.

## 그림 조각 공개

- 기존 `preview` 이미지와 기본 SVG, 사용자 이미지 Blob URL 관리는 유지합니다.
- 이미지의 opacity는 1로 고정합니다. 이미지를 감싸는 같은 크기의 영역 위에 불투명한 마스크 격자를 배치합니다.
- main은 5×5, boss는 3×3. 각 카드의 `board_N`과 격자 N번째 셀을 일대일로 연결합니다.
- 카드 removed=false이면 그 셀을 가리고, removed=true이면 마스크 셀을 투명하게 하여 실제 이미지의 해당 영역만 보이게 합니다.
- 아직 카드가 제거되지 않은 초기 상태는 전부 가려지고, 클리어 상태는 이미지 전체가 보여야 합니다. 전체 opacity나 퍼센트만큼 좌측부터 드러내는 방식은 사용하지 않습니다.
- 이미지와 격자 영역은 같은 좌표와 크기를 공유해야 합니다. 기본 400:220 비율과 object-fit:cover 사용을 허용합니다. 사용자 이미지 비율이 달라도 마스크와 이미지 표시 영역이 맞아야 합니다.
- 오버레이는 pointer-events:none, aria-hidden=true로 처리하며 포커스나 게임 클릭을 가로채지 않습니다.
- 규칙과 DOM을 분리합니다. reveal.js에 상태를 받아 공개 셀 목록을 만드는 순수 함수를 추가하고, artwork.js 등에 격자 DOM 갱신을 둡니다.
- 공개 비율은 기존 calculateReveal을 유지합니다. 보스 1장 공개는 1/9 면적이 드러나고 표시 숫자는 반올림한 11%가 됩니다.
- Draw/음소거/튜토리얼 단계 이동은 공개 셀을 바꾸지 않습니다. 다시하기는 마스크를 복원하고 다음 단계는 새 격자로 바꿉니다.
- 재실행 후 행동 로그를 복원한 시점에 같은 셀이 즉시 드러나야 합니다. 저장된 action 로그나 게임 상태에 DOM 마스크 정보를 추가하지 않습니다.
- 같은 보드에서 DOM을 재생성하지 않고 클래스 변경 등으로 필요한 셀만 갱신합니다. 새 제거에만 짧은 CSS 전환을 쓰고, 최초 로딩/복원에는 불필요한 공개 애니메이션을 재생하지 않습니다.
- prefers-reduced-motion에서는 전환/애니메이션을 끕니다. 상시 루프나 JS 프레임 애니메이션은 추가하지 않습니다.
- 공개 상태를 설명하는 접근성 텍스트를 제공하고, 375px 모바일/확대/가로세로 화면 전환에서도 격자와 카드가 넘치지 않게 합니다.

## 튜토리얼

- 4개 이하의 짧은 설명: 중앙 숫자 ±1 및 1↔13, 카드 제거와 그림 조각, 막힐 때만 가능한 Draw와 유한 덱, 클리어/다음 단계/기기 내 자동 저장.
- 게임을 막지 않는 인라인 안내 패널로 구현합니다. 설명 이동은 게임 상태/행동 로그/레벨/저장을 변경하지 않습니다.
- 처음 하는 사용자에게만 자동 표시합니다. 게임 저장 복원을 마친 뒤 현재 첫 단계, actions가 비었고 completedLevelIds가 비었으며 튜토리얼 완료 기록이 없을 때 자동 표시합니다. 진행 중인 복원 판에는 자동으로 끼어들지 않습니다.
- '다음 설명', 마지막 '시작하기', 항상 가능한 '건너뛰기'를 제공합니다. 건너뛰기/완료 모두 다음 자동 표시를 생략하게 기록합니다.
- '도움말' 버튼으로 언제든 처음 설명부터 다시 열 수 있습니다. 다시 열고 닫아도 게임 진행, 그림 마스크, 음소거, 완료 기록은 유지합니다.
- 패널이 비동기로 늦게 뜨면서 사용자의 조작을 가로채지 않게 합니다. 사용자가 이미 플레이하거나 도움말을 열었으면 이전 비동기 초기화가 이를 덮어쓰지 않아야 합니다.
- 버튼은 키보드 사용 가능, 안내는 aria-live=polite. 사용자 요청으로 열고 닫을 때 포커스를 일관되게 관리하고 자동 표시는 게임 포커스를 빼앗지 않습니다. 비모달 패널에 포커스 트랩을 만들지 않습니다.

## 튜토리얼 기록

- 게임의 schemaVersion=1 저장 형식과 `picture-blast-solitaire.save` 키는 변경하지 않습니다.
- 별도 `picture-blast-solitaire.tutorial` 키에 `{schemaVersion:1,completed:true}`만 저장합니다.
- 기존 createLocalStorageAdapter를 주입 가능하게 재사용하되, 게임용 createSaveStore의 슬롯 형식과 튜토리얼 레코드를 혼용하지 않습니다. 두 키의 읽기/쓰기 차단 상태도 서로 분리합니다.
- 저장 접근/쓰기 실패 시 안내는 메모리에서 종료되며 게임은 계속됩니다. 재실행 시 안내가 다시 나타날 수 있음을 짧게 알립니다.
- 미래 버전 레코드는 덮어쓰지 않습니다. 이미 기록이 있다고 취급해 자동 표시는 생략하고 수동 도움말은 허용합니다. 게임 세이브의 쓰기에는 영향을 주지 않습니다.
- 깨진/잘못된 레코드는 미완료로 취급하고, 실제 완료/건너뛰기 때만 새 레코드를 씁니다. 렌더링이나 게임 시작만으로 기록을 쓰지 않습니다.

## 적용 및 검증

- 기존 기본 그림과 QA 업로드만 사용합니다. 새 이미지 생성/다운로드, 외부 폰트/라이브러리를 추가하지 않습니다.
- HTML/CSS/ES modules 유지. HubGame/계정/리더보드/Firebase/네트워크 저장을 추가하지 않습니다.
- save.js, rules.js, levels.json의 기존 동작을 유지합니다. 필요한 새 모듈은 scripts/check-repo.mjs에 포함합니다.
- 변경 파일만 전체 코드로 제공합니다. 코드 내부 주석과 한 글자 변수명은 추가하지 않습니다.
- 새 테스트 프레임워크/테스트 파일 없이 실행 가능한 Node assert 검증 코드를 별도 제공합니다. 실행하지 않은 검증을 통과했다고 주장하지 않습니다.
- 검증 항목: 25/9 셀 수, 선택 셀만 공개, Draw/옵션에서 불변, 재시작/레벨 전환, 행동 재생 후 같은 공개 상태, 원본 불변성, 튜토리얼 건너뛰기/완료/재개/수동 재열기, 키 분리/저장 오류/미래 버전/늦은 초기화.
