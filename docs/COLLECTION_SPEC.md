# 아트 컬렉션과 해금 구현 기준

상태: 컬렉션 기능 구현 및 검증 완료. 현재 6개 항목은 기능 검증용 기본 아트 한 장을 공유하며, 출시용 개별 아트는 별도 제작이 필요합니다.

## 범위와 콘텐츠 상태

고정 스테이지를 클리어하면 대응하는 그림을 수집하고 컬렉션에서 볼 수 있게 합니다. 재방문 동기의 기반을 만들되, 이번 작업은 컬렉션 기능과 기존 클리어 기록 연결에 한정합니다.

현재 사용할 수 있는 기본 아트는 media.js의 추상 SVG 한 장입니다. 기능 검증용 6개 항목은 이 기본 이미지를 함께 참조합니다. 이는 6개의 서로 다른 출시용 아트를 확보했다는 뜻이 아닙니다. 실제 출시용 개별 아트 제작/라이선스 확인/교체는 별도 작업입니다. Gemini는 새 이미지나 코드로 그린 그림을 추가하지 않습니다.

## 카탈로그

- `web-prototype/data/artworks.json`에 `{version:1, artworks:[...]}` 형식으로 6개 항목을 둡니다.
- 각 항목은 `{id,levelId,title,assetKey}`만 사용합니다. id는 `art_level_1` 등 안정적인 문자열입니다. 각 levelId는 현재 6개 레벨과 일대일 대응합니다.
- 이번 assetKey는 `prototype-default`만 허용하고, 코드에서 기존 getDefaultImageSvg()로 해석합니다. 카탈로그에 URL/HTML/Blob URL/사용자 파일 참조를 넣지 않습니다.
- 레코드 타입/빈 문자열/문자열 길이/버전/중복 id/중복 levelId/알 수 없는 레벨/미지원 assetKey/누락된 대응 항목을 검증합니다.
- 컬렉션 순서는 레벨 순서로 일관되게 정합니다. 카탈로그 배열 순서가 달라도 스테이지 순서를 유지합니다.
- 기존 levels.json, 규칙, levelSignature, solution과 게임 저장 스키마는 변경하지 않습니다.

## 해금 상태

- 해금 여부는 검증된 `saveSlot.completedLevelIds`에서 파생합니다. 별도 unlockedArtIds 목록이나 별도 보상 저장 키를 만들지 않습니다.
- 해당 levelId를 클리어한 경우에만 unlocked=true입니다. 진행 중/blocked/failed 상태에서는 해금하지 않습니다.
- 처음 클리어하여 목록에 id가 추가되는 순간 해당 항목을 해금합니다. 기존 checkClearAndSave의 중복 방지를 유지하고, 반복 클리어로 새 보상을 재지급하지 않습니다.
- 저장된 클리어 기록을 복원하면 이미 수집한 항목을 그대로 표시합니다. 게임 로딩만으로 보상 알림이나 게임 저장을 반복하지 않습니다.
- 클리어 기록을 로컬에서 조작할 수 있으므로 이것을 구매 권한이나 서버 검증된 보상으로 사용하지 않습니다.
- 게임 저장 실패/미래 버전 쓰기 차단 시에도 이번 메모리 세션의 해금은 표시하되 기존 저장 경고를 숨기거나 영구 보존을 보장하지 않습니다.

## UI

- '컬렉션' 토글 버튼과 현재 수집 수 `수집 N / 6` 표시를 추가합니다. 인라인 패널로 열고 닫아 현재 플레이를 방해하지 않습니다.
- 열기/닫기/항목 선택은 현재 판, 행동 로그, center, 덱, 공개 마스크, 옵션, 사용자 이미지와 게임 저장을 바꾸지 않습니다. 별도 화면 선택 상태를 세이브에 넣지 않습니다.
- 잠긴 항목은 번호/자물쇠/해금 조건 텍스트만 표시하며 전체 그림이나 이미지 요소를 노출하지 않습니다.
- 해금 항목은 기본 아트 썸네일과 제목을 표시하고, 버튼으로 선택하면 패널 안의 큰 보기와 캡션을 제공합니다. 큰 보기에는 닫기를 제공하고 포커스를 선택한 항목으로 복원합니다.
- 썸네일/큰 보기 이미지는 컬렉션 카탈로그의 동봉 아트입니다. 플레이 중 사용자 업로드 이미지를 컬렉션에 복사하거나 저장하지 않습니다.
- 새 항목 해금은 별도 aria-live=polite 안내로 짧게 알립니다. statusPanel/saveStatus/imageStatus/tutorialStatus를 덮어쓰지 않습니다.
- 튜토리얼과 컬렉션 패널은 독립적으로 열리고 닫혀야 하며, 튜토리얼 다시 열기가 컬렉션 선택이나 게임을 초기화하면 안 됩니다.
- button type, 키보드 조작, aria-expanded/aria-controls, 이미지 대체 텍스트, 숨김 영역의 포커스 복원을 처리합니다. 모달/포커스 트랩/게임 화면 차단은 추가하지 않습니다.
- 375px에서는 2열 이하의 썸네일 격자를 사용하고 가로 넘침을 막습니다. 사용자 확대와 모션 감소 설정을 유지합니다.

## 모듈과 로딩

- collection.js 등에서 카탈로그 검증, 해금 목록/수집 수 계산을 DOM 없는 순수 함수로 분리합니다.
- 컬렉션 DOM 렌더링과 이미지 소스 해석은 규칙 엔진에서 분리합니다. 카탈로그 제목은 textContent로 처리합니다.
- 카탈로그는 앱에 동봉한 상대 경로에서 로드합니다. 외부 통신/계정/HubGame/Firebase/리더보드를 추가하지 않습니다.
- 컬렉션 로딩은 게임의 레벨/세이브 복원과 오류를 분리합니다. 카탈로그 로딩 실패나 잘못된 형식이 게임을 멈추거나 레벨 재시도 화면으로 바뀌면 안 됩니다.
- 컬렉션 실패 시 전용 영역에 재시도 안내를 표시합니다. 유효하지 않은 카탈로그를 임의의 대체 아이템으로 숨기지 않습니다.
- 중복 재시도/늦은 응답이 최신 게임 상태를 덮어쓰지 않게 합니다. 늦게 로드된 카탈로그는 그 시점의 completedLevelIds를 기준으로 표시합니다.
- 새 모듈과 데이터는 scripts/check-repo.mjs에 포함합니다. 구조 점검 시 카탈로그의 레벨 참조도 검증합니다.

## 제외 범위와 검증

- 유료 잠금, IAP/광고/코인, 보상 랜덤 상자, 새 스테이지, 이미지 생성/다운로드, 썸네일 공유/내보내기는 추가하지 않습니다.
- save.js/rules.js/levels.json은 기존 동작을 유지합니다. 새 라이브러리/TypeScript/상시 루프/코드 내부 주석/한 글자 변수명을 추가하지 않습니다.
- 변경 파일만 전체 코드로 출력하고 변경 없는 원본은 재출력하지 않습니다. 실행하지 않은 검증을 통과했다고 주장하지 않습니다.
- 새 테스트 파일/프레임워크 없이 Node assert 실행 코드를 별도 제공합니다.
- 검증: 0/6 초기 상태, 클리어 후 1/6, 재클리어 중복 방지, 기존 기록 복원, 6/6 완료, 미완료/실패 미해금, 입력 불변성, 잘못된 카탈로그 거부, 실패/지연 로드, 컬렉션 조작 시 게임/세이브/사용자 이미지/마스크 불변, 접근성/포커스.
