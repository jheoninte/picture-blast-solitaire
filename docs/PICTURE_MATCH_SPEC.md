# 그림 위·아래 짝맞추기 전환 명세

> 폐기된 클릭 제거 방식의 역사 문서입니다. 사용자가 드래그 교환·세로 완성·낙하 및 빈칸 이동 불가를 확정했습니다. 최신 기준은 PICTURE_SWAP_SPEC.md입니다. 아래의 무중력/임의 두 장 클릭 제거/이전 저장 키 지시는 새 구현에 적용하지 않습니다. 아래 완료 표시는 이전 방식에만 해당합니다.

상태: 그림 짝맞추기 구현·통합과 Windows 웹 검증 완료. 기본 index.html에서 새 게임을 실행하며, 숫자 ±1 프로토타입은 legacy-solitaire.html에 보존합니다. 현재 그림은 개발용 참고 이미지 가공본으로 출시용 콘텐츠 완료를 뜻하지 않습니다.

## 목적과 이번 범위

사용자는 현재 화면만으로 어떤 게임인지 알 수 없다고 지적했고, 그림 위·아래 조각 짝맞추기로 변경을 선택했습니다. 상점보다 실제 그림이 보이고 손으로 플레이할 수 있는 모바일 화면이 우선입니다. 첫 검증을 위한 아래 세부 규칙은 Codex가 정한 구현 기본값이며 첨부 이미지에서 확인한 원작의 규칙이라고 주장하지 않습니다.

무거운 코딩은 Gemini, 범위·자료 준비·검토·적용·검증은 Codex가 맡습니다. 기존 패키지/프레임워크는 그대로 사용합니다. 이번 결과는 수익화/리텐션 입증이나 출시 완료를 뜻하지 않습니다.

## 코어 규칙

- 모든 남은 카드는 앞면 그림이 보이며 선택할 수 있습니다. 뒤집기 기억력 게임이 아닙니다. 인접/맨 위 카드/슬롯/중력 제한은 이번에 넣지 않습니다.
- 카드 형식은 `{id, artId, half:'top'|'bottom'}`. id는 판 안에서 유일합니다. 같은 artId이고 half가 반대인 서로 다른 두 장만 완성할 수 있습니다. 같은 half 두 장, 다른 그림, 같은 카드 두 번은 완성이 아닙니다.
- 하나를 누르면 선택 테두리. 같은 카드를 다시 누르면 선택 해제. 다른 카드를 눌렀을 때 맞으면 두 장을 제거하고 완성 그림을 잠시 보여주며 진행 수를 올립니다. 틀리면 제거하지 않고 두 번째 카드를 새 선택으로 유지합니다. 짧은 불일치 표시가 가능하나 입력을 막는 대기 시간은 넣지 않습니다.
- 같은 artId의 복사본이 여러 개면 어느 위 조각과 어느 아래 조각도 짝이 됩니다. 시각적으로 같은데 내부 pairId가 다르다는 이유로 거절하지 않습니다.
- 맞춘 카드는 비어 있는 자리로 남습니다. 나머지가 갑자기 당겨지거나 낙하하지 않습니다.
- 모든 카드가 제거되면 cleared, 아니면 playing. 제한 시간/목숨/실패 페널티/유료 재시도/중앙 숫자/Draw/덱을 넣지 않습니다. 숫자를 카드에 표시해 그림 인식을 대신하지 않습니다.
- 순수 규칙 함수는 DOM·오디오·저장·랜덤 전역에 의존하지 않고 입력 불변성을 유지합니다. 보스도 같은 규칙을 씁니다.

## 첫 콘텐츠와 그림

- `web-prototype/data/picture-match-artworks.json`과 `web-prototype/assets/picture-match/reference-vases/`의 실제 PNG 12장을 사용합니다. 개발용 이미지 파일은 이미 로컬 저장소에 있습니다. Gemini는 PNG를 새로 그리거나 Base64로 재출력할 필요가 없습니다.
- manifest의 6종: vase_stripes, vase_spiral, vase_orange, vase_mint, vase_speckles, vase_ivory. 각 top/bottom은 128×176 불투명 PNG입니다. assets 경로는 web-prototype/index.html 기준입니다.
- 아트 출처: 사용자가 첨부한 참고 스크린샷에서 조각을 잘라 크기를 맞췄습니다. art_source=existing, route=user-reference-crop. 이미지 생성 모델은 사용하지 않았습니다. `releaseApproved:false`를 true로 바꾸거나 생성 아트/자체 제작/라이선스 확보로 표현하지 않습니다.
- provenance는 docs/dev-art/picture-match-reference-provenance.json, 검토용 시트는 docs/dev-art/picture-match-reference-contact.png입니다. 첫 기능 검증용이며 출시 전에 직접 확보한 아트로 교체합니다. 원작 로고/코인/상품 UI를 잘라 재사용하지 않습니다.
- 완성 미리보기는 동일 화병 top/bottom을 세로로 빈틈없이 합쳐 보여줍니다. 전체 이미지를 서로 다른 비율로 늘리거나 object-fit:cover로 조각 경계를 다르게 자르지 않습니다. 각 카드의 이미지 비율 128/176을 유지합니다.
- 이미지 로딩 실패 시 해당 카드를 투명/빈 버튼으로 숨기지 말고 이미지 재시도 안내를 보여줍니다. 오류가 나도 기존 저장을 덮어쓰지 않습니다. 외부 이미지/CDN/이미지 API/폰트 다운로드를 사용하지 않습니다.

## 고정 레벨

- 새 `picture-match-levels.json`, version=1. 기존 levels.json은 그대로 둡니다.
- level_1: main, 4열×3행, 화병 6종 한 쌍씩 총12장/6쌍.
- level_2: main, 6열×4행, 화병 6종 두 쌍씩 총24장/12쌍.
- level_3: boss, 6열×6행, 화병 6종 세 쌍씩 총36장/18쌍.
- 각각 서로 다른 고정 섞기 배치를 담습니다. 코드 실행마다 최초 배치를 임의 생성하지 않습니다. 시작부터 같은 그림의 위·아래를 모두 정렬해 답을 보여주지 않습니다.
- 검증: 지원 버전, 비어 있지 않은 유일 레벨 id, 유일 카드 id, 타입/길이, columns·rows 범위와 cards.length 일치, mode, 존재하는 artId, half 종류, 그림별 top/bottom 수 일치, 짝수 카드 수. 잘못된 판을 임의 보정하지 않습니다.
- 순수 해 경로 생성/재생으로 남은 모든 쌍을 지울 수 있음을 check-repo에서 검증합니다. 제한 없는 매칭이라 쌍 수 균형이면 해가 있지만 실제 제거 API도 재생합니다.

## 플레이 화면

- 데스크톱에도 가운데 정렬된 세로형 게임 화면을 사용합니다. 기존 개발자 사이드바와 숫자 카드 격자를 새 게임의 주 화면으로 쓰지 않습니다.
- 녹색 테이블, 밝은 카드 테두리, 실제 화병 그림, 상단 레벨/완성 쌍 N/M, 하단 힌트·섞기·도움말·설정/다시하기 접근을 구성합니다. 메뉴 구조는 작게 유지하고 현재 실제로 동작하는 항목만 표시합니다.
- 첫 판 상단에 '같은 화병의 위·아래 조각을 눌러 완성하세요'를 짧게 표시합니다. 사용자가 숫자 규칙을 읽지 않아도 그림으로 이해할 수 있어야 합니다.
- 첨부 예시는 분위기와 그림 중심 배치의 참조입니다. 미구현 코인/상점/카드 슬롯/화살표/3회 부스터 잔량을 장식으로 복제하지 않습니다.
- 힌트는 남은 합법 쌍 두 장을 잠깐 강조합니다. 무료이며 카드를 자동 제거하거나 게임 저장을 바꾸지 않습니다. 연속 클릭/레벨 변경/재시작 시 이전 타이머가 새 강조를 덮지 않게 정리합니다.
- 섞기는 남은 카드의 위치만 섞고 artId/half/완성 기록/짝 균형은 유지합니다. 선택과 힌트는 해제합니다. 제거된 빈자리는 유지하고 남은 위치 사이에서만 섞습니다. RNG를 주입해 검증하며 Math.random은 UI 경계에서만 사용합니다. 새 배치를 저장해 재실행 시 복원합니다.
- 이번 힌트/섞기는 무료입니다. 광고·구매·사용 횟수 재화는 붙이지 않습니다.
- 클리어 시 완성 결과, 다음 스테이지(마지막은 팩 완료), 같은 판 다시하기를 제공합니다. 완료 화면을 닫거나 다음으로 가는 동작을 분명하게 합니다.
- 옵션의 사운드/햅틱 토글을 재사용하고 비지원 환경의 예외를 흡수합니다. 오디오와 타이머는 사용자 동작/필요한 짧은 연출에만 사용하고 상시 루프는 넣지 않습니다.
- 375×812와 데스크톱에서 확인합니다. 6열일 때 텍스트 번호 대신 그림을 크게 사용하고 카드 폭을 확보합니다. 가로 넘침 없음, 가능하면 812px 높이에서 보드·주요 버튼이 함께 보이게 하되 작은 높이/텍스트 확대에서는 세로 스크롤을 허용합니다. 사용자 확대를 차단하지 않습니다.
- 버튼 type, 키보드/터치, 의미 있는 이미지·버튼 이름, aria-pressed 선택 상태, 제거된 카드 포커스 처리, polite 상태 안내, 모션 감소를 처리합니다. 장식과 선택 안내를 색상에만 의존하지 않습니다.

## 저장과 레거시 경계

- 기존 숫자 게임의 main.js/rules.js/save.js/levels.js/tutorial.js/collection.js와 JSON을 바꾸지 않습니다. 새 모듈은 `js/picture-match/`에 두고 CSS도 별도 파일로 둡니다.
- 현재 index.html을 `legacy-solitaire.html`로 보존한 뒤, index.html을 새 게임 진입점으로 바꿉니다. 상대 경로는 같은 디렉터리이므로 레거시 모듈은 그대로 쓸 수 있습니다. 이미 legacy-solitaire.html이 있으면 덮어쓰지 않습니다.
- 새 게임은 `picture-blast-solitaire.picture-match.save` 키, schemaVersion=1을 사용합니다. 이전 save/tutorial 키를 읽어 새 규칙의 완료 기록으로 해석하거나 삭제/덮어쓰지 않습니다.
- 저장 필드: currentLevelId, levelSignature(카드 원본·배치·보드 크기·mode), completedLevelIds, removedCardIds, cardOrder, options:{soundOn}. 현재 선택/힌트/연출/이미지 바이너리/Blob URL/구매 권한은 저장하지 않습니다.
- cardOrder는 현 레벨 카드 id의 정확한 순열, removedCardIds는 중복 없는 유효 id 목록이며, 제거된 그림별 top/bottom 수가 같아야 합니다. UI count·remaining·status는 검증된 값에서 파생합니다. completedLevelIds는 새 레벨 whitelist로 정규화합니다. 규칙이 다른 레거시 기록은 자동 이관하지 않습니다.
- 지원하지 않는 미래 버전/과대 저장(100KB)/읽기 접근 실패는 덮어쓰지 않고 쓰기를 차단해 세션 메모리로 플레이합니다. 손상된 현재 버전/레벨 signature 불일치는 안내 후 현 판을 재설정합니다. writes 실패는 안내하고 다음 변경에서 재시도합니다. 비동기 저장을 직렬화하고 스냅샷을 요청 시점에 잡습니다.
- 복원 중 자동 저장하지 않습니다. 성공한 매칭·섞기·옵션·레벨 전환/재시작에서만 저장합니다. 선택/불일치/도움말/힌트는 게임 저장을 바꾸지 않습니다. 중복 완료 id/중복 클리어 알림을 막습니다.
- 새 게임의 컬렉션/사용자 이미지 업로드 연결은 이번에 보류합니다. 기존 컬렉션과 사용자 이미지 기능은 레거시에 남습니다. 새 화면에 동작하지 않는 버튼을 표시하지 않습니다.

## 제출과 검증

- 상점 명세와 이전 숫자 규칙은 이번 주 게임 구현보다 우선하지 않습니다. HubGame/랭킹/클라우드/Firebase/외부 전송/의존성/SDK를 넣지 않습니다.
- AGENTS.md, 이 명세, 최신 원본만 기준으로 삼습니다. 제공되지 않은 game-studio.md 등에서 추가 요구사항을 가져오거나 읽었다고 주장하지 않습니다.
- 변경 파일만 전체 코드로 반환합니다. 새 레벨 JSON은 전체를 반환합니다. 이미지 PNG는 이미 존재하므로 재출력하지 않습니다. 코드 내부 주석/한 글자 변수명/새 테스트 프레임워크는 추가하지 않습니다.
- check-repo는 새 manifest/PNG 경로 존재/레벨 검증·해 경로 재생을 추가하고 레거시 검사도 유지합니다. PNG MIME은 dev-server에서 지원합니다. 빌드가 로컬 아트를 포함하는지 확인합니다.
- 별도 Node assert 실행 코드를 제공합니다: 모든 매칭 조합·복사본 교차 매칭·입력 불변성·불일치/선택 해제·힌트 비파괴·섞기 균형/복원·전 레벨 클리어·잘못된 데이터/이미지 누락·현재/손상/미래 저장·저장 거부/직렬화·레거시 키 불변성·중복 완료.
- 실제 실행하지 않은 테스트는 미실행으로 표시합니다. Windows 웹 플레이 검증과 iOS 네이티브 검증을 구분합니다.
